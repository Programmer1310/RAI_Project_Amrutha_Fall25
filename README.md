# Fairness Under Unawareness: Thresholded vs. Weighted BISG

Responsible AI & the Law — NYU, Fall 2025
Amrutha Shyam and Anna Susan Cherian

Many administrative datasets omit race, yet fairness audits need it. Bayesian Improved Surname
Geocoding (BISG) infers a probability vector over racial groups from a person's surname and
location. This project asks how the choice of turning those probabilities into race labels —
**threshold/argmax (hard)** vs. **probability-weighted (soft)** assignment — changes the disparities
a fairness audit reports.

Using the North Carolina voter file (which includes self-reported race as ground truth), we:

1. Combine the 100 county voter files (~8.9M records) and draw a sample of ~760K voters.
2. Run BISG on surname + ZCTA to get race probabilities.
3. Train ML models to predict party affiliation.
4. Measure race-by-party disparity (predicted − actual party share) using self-reported race,
   hard (argmax) BISG race, and soft (probability-weighted) BISG race, and compare them.

## Data

The voter data is not included in this repository (size and personal records). Download the
statewide county files from the NC State Board of Elections:
https://www.ncsbe.gov/results-data/voter-registration-data — and place them in
`Project Implementation/ncvotersheets/`. Intermediate CSVs (`bisg_done_sample_760193.csv`,
`nc_voted_with_predicted_party.csv`) are regenerated by the notebooks.
